## 1. 运行时拓扑

```
[3000 服务器] apps/web/                  desk=00000000-0000-0000-0000-000000000001  "飞翔 CEO" 
   ↓ HTTP POST /api/v2/missions (peer_token auth)
[3001 服务器] apps/web-peer/             desk=00000000-0000-0000-0000-000000000002  "对端 CEO"
                                        upstream_token = 586ad80b-58b4-4c63-a4f5-6d5660b4345d
                                        飞翔 desk upstream_token = 77874aa2-acb... (没用到)

完成回调反向: 3001 → POST 3000/api/v2/peer/done (带 token), 3000 mark assignment completed
```

`apps/web-peer/` 是 `apps/web/` 的 **rsync 克隆** (node_modules 是符号链接), 因为 Next 不允许同目录两个 `next dev`. **不要把 web-peer/ 当独立代码改** — 永远从 web/ rsync 过去.

**rsync 同步命令** (项目根目录下):
```bash
rsync -a --delete \
  --exclude='node_modules' --exclude='.next' --exclude='.turbo' \
  apps/web/ apps/web-peer/
```

## 5. 还没做 / 已知问题

### 没 commit
所有改动都未 commit. 你新机器拉代码后:
```bash
git status              # 看现有未提交修改
git add ...              # 选择性提交, 或建分支整个 stash
```
建议分支策略: 在 `v3-peer-network` 分支基础上提一个 commit, e.g. `feat: unified my-work view + mission-chat binding + PWA + bug intake`.

### 半成品 / 已知缺陷
1. **Chat action tool 链式调用 refactor 中途** — `apps/web/app/api/v2/chat/route.ts` 加了 `feedAndContinue` / `actionContents` / `sideEffects` 三个 helper 但没用. action tool 还是立即 return, 一轮只能调 1 个工具. 后果: AI 不能"先 dismiss 再 hire". 完成方式: 把每个 action 分支的 `return NextResponse.json(...)` 改成 `recordAction(content, extra); feedAndContinue(JSON.stringify({ok:true,extra})); continue;`, 让 LLM 看到结果继续推理.

2. **Capacitor 没起** — 用户要 native iOS/Android 壳. 标准做法:
   ```bash
   cd apps/web
   pnpm add @capacitor/core @capacitor/cli @capacitor/android @capacitor/ios
   npx cap init Mibusy com.mibusy.app --web-dir public
   # 编辑生成的 capacitor.config.ts:
   #   server: { url: "http://<你的LAN/Tailscale IP>:3001", cleartext: true }
   npx cap add android
   npx cap add ios       # 需要 Mac + Xcode
   npx cap open android  # → Android Studio 编译 .apk
   npx cap open ios      # → Xcode 编译 + TestFlight
   ```
   **注意**: 这个方式手机是 WebView 壳, 后端仍跑在你电脑上 (server.url). 真"device-to-device peer" 需要 nodejs-mobile 或 SQLite + 重写 API, 是更大的项目.

3. **跨 desk 数据泄露 — 只修了 2 处** — `getRunningAssignments` + `getRecentHandoffs`. 其他 query 没仔细审一遍, 可能还有. 检查方式: `grep -n "FROM assignments" apps/web/lib/v2-data.ts`, 看哪些 WHERE 没有 desk_id.

4. **Hybrid mode 没有切换 UI shortcut** — 重建 agent 时只能选 facade/hybrid, 改 mode 要"切回 AI → 重连". `configure_peer_agent` chat 工具仍硬编码 facade (line 787).

5. **3001 dev server 重启脚本** — 每次 rsync 时 Turbopack 可能 HMR 不追新文件, 要手动重启. 见上面 "Dev servers" 那节的命令.

## 6. 移机器步骤 (你下一台机器要做的)

```bash
# 1. 克隆 repo
git clone <repo url> mibusy
cd mibusy
git checkout v3-peer-network
# (可选) 应用未提交修改 — 见下面"未提交改动包"

# 2. 装依赖
pnpm install                 # 或 npm i, 看 lock 文件

# 3. 起 Postgres
docker compose up -d db

# 4. 应用 migrations (0001 → 0023, 按顺序)
for f in packages/db/migrations/*.sql; do
  bash scripts/apply_migration.sh "$f"
done

# 5. 恢复数据 (你从这台带 dump 走)
psql $DATABASE_URL < mibusy-dump-2026-05-14.sql

# 6. .env.local
echo 'DATABASE_URL=postgresql://postgres:postgres@localhost:5432/solo_agent' > apps/web/.env.local
echo 'DEEPSEEK_API_KEY=sk-...' >> apps/web/.env.local

# 7. rsync web-peer
rsync -a --delete --exclude=node_modules --exclude=.next --exclude=.turbo apps/web/ apps/web-peer/
mkdir -p apps/web-peer/node_modules
# symlink web/node_modules to web-peer/node_modules (省磁盘):
ln -sfn $(realpath apps/web/node_modules)/* apps/web-peer/node_modules/

# 8. 启动
bash scripts/v3_demo.sh      # 或两个终端分别跑 dev
bash scripts/restart_worker.sh

# 9. 验证
curl http://localhost:3000/chat   # 200
curl http://localhost:3001/chat   # 200
```

## 9. 联系点 / 常见坑

- **Turbopack HMR 偶尔丢新文件**: 加新组件后, 如果 3001 显示老的, 重启 dev server (kill + 重新启动)
- **3001 是 rsync 出来的**: 不要在 web-peer/ 里改东西, 永远 web/ 改完 rsync 过去
- **peer_token UUID 校验**: 复制 token 时不要带 `/my/` 前缀 (CeoSheet 已修, 但旧浏览器缓存可能还旧)
- **DeepSeek API**: 这台机器用的 key 是用户自己的 (`sk-ea480f...`). 新机器你换自己的 key
- **多次解雇 → peer config 被撤销**: dismiss_agent 会一并删 peer connection 行, 重建 agent 后要重配 peer
